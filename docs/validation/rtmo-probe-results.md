# RTMO-M: isolated pose-model probe

25 November 2026. This is a candidate-model experiment, not a production acceptance test. It uses the official OpenMMLab RTMO-M ONNX SDK package (`end2end.onnx`), SHA-256 of its downloaded ZIP verified by [`run-probe.ps1`](../../scripts/experiments/rtmo/run-probe.ps1). The probe was executed on the ten fixed 640×360 BGR frames (`compare10` through `compare190`) used by the existing pose comparison, with one warm-up and ten measured inferences for every frame.

The direct `docker run` completed with exit code 0. ONNX Runtime listed and selected `CUDAExecutionProvider`; it also warned that it inserted ten Memcpy nodes and that some nodes are assigned outside the preferred provider. The latter can be expected for shape operations, but this probe does not prove that every operation uses the GPU. Treat it as a CUDA-backed run with possible CPU fallback, not a pure-GPU measurement.

## Result

| Candidate | Frames | Runs per frame | Median model invocation | Mean model invocation | Reported detections |
| --- | ---: | ---: | ---: | ---: | ---: |
| RTMO-M | 10 | 10 | 8.376 ms | 8.373 ms | 225 (18–27/frame) |

The raw detections are in [rtmo-m-comparison.json](rtmo-m-comparison.json), SHA-256 `D630C3182A81D4CDA3175CDD9B96806657C780A7D20EE30577471E0D20A8DE2E`.

For orientation only, the earlier C# results on the same ten frames report a 37.306 ms median and 89 person detections for the two-model baseline, and a 7.185 ms median and 67 detections for YOLO26s-pose. Those timings are not directly comparable: the RTMO value measures only `session.run`; it excludes BGR resize/padding, tensor construction, RTMO decoding, NMS, seating heuristic, JSON serialization and disk output. The C# `totalMs` excludes input preparation but includes the existing model calls and their decoding. All three measurements exclude model loading and are not multi-camera throughput tests.

RTMO's 225 detections differ strongly from both existing model outputs. They are neither precision nor recall: this sample has no exhaustive person/keypoint ground truth, and the matching thresholds and postprocessing differ. The observed speed is sufficient reason to add RTMO to a labelled comparison, but not to replace the current person pipeline.

## Reproducibility and script behavior

`scripts/experiments/rtmo/run-probe.ps1 -Variant m -Runs 10 -CompareFrames` builds and runs the isolated image and now explicitly propagates a non-zero exit code from both `docker build` and `docker run`. The reported JSON was generated by the already-built `foodvision-rtmo-probe` image using a direct `docker run`, so that final successful execution did not rebuild the image.
