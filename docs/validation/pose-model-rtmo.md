# RTMO-M as a replacement for two person models

25 November 2026. Fixed-frame candidate check, not a production acceptance test. RTMO-M's official OpenMMLab ONNX SDK package supplied the model, pipeline and thresholds. Its SDK pipeline specifies `BottomupResize` to 640×640, BGR input, top-left padding with value 114, no mean/std transform, detection score threshold 0.1 and NMS IoU 0.65. [`probe.py`](../../scripts/experiments/rtmo/probe.py) implements those settings and uses the model's `dets` output for boxes, then its `keypoints` output for hips and the existing FoodVision knee-angle rule.

The ten fixed 640×360 BGR frames at video times 10 through 190 seconds were the same as the baseline and YOLO26s checks. RTMO was warmed up once and then run ten times per frame. Its median `session.run` time was **8.38 ms**; the baseline's median of the pose call plus person-detector call and their existing decoding was **36.97 ms**. The timings are directional only: RTMO's number excludes image preparation, output decoding, NMS and seating calculation, so it is not an end-to-end or multi-camera comparison.

At the SDK pipeline's threshold RTMO emitted 225 detections, versus 89 from the current two-model baseline. Greedy one-to-one matching with IoU ≥ 0.5 paired 70 detections. Of those, 29 had a different `Seated` flag. This is disagreement with the existing implementation, not precision or recall: no independently labelled people, keypoints or table states exist for these frames. The high number of RTMO detections needs an ROI-aware labelled evaluation and threshold tuning before any replacement.

The run required `CUDAExecutionProvider`; ONNX Runtime reported that it selected CUDA, while also noting ten inserted memcpy nodes and some non-CUDA nodes. The measurement is CUDA-backed but does not prove all operations ran on the GPU. It is enough to establish that the official ONNX artifact runs and produces person boxes plus 17 keypoints in one invocation.
