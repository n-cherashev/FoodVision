# Experiment 3: FP16 model execution

24 November 2026. Inspected ONNX initializers: `yolo11x-pose.onnx` already contains predominantly FLOAT16 weights (372 FLOAT16 initializers), while `yolo11x.onnx` and `yolo26l-detect.onnx` predominantly contain FLOAT32 weights. The existing runtime already enables ONNX Runtime graph optimizations for the object and pose models.

Converted copies of the object and person models with `onnx` 1.23.2 and `onnxconverter-common` 1.16.0 using [experimental-fp16.py](../../scripts/experimental-fp16.py), which retains FLOAT32 input/output and `Resize` ROI/scales. The converter warned that some small values were truncated. The originals remain untouched. The converted object model loaded; the converted person model failed ONNX Runtime loading with a type mismatch at `/Cast_3`. A further attempt with `--repair-cast-types` got past that error but failed at `/Div` with mixed FLOAT16 and FLOAT inputs. The converter's default blocked-op configuration also failed on the object model at a `Resize` output. No conclusion about FP16 person-detector speed can be drawn from these failed conversions.

In a 30-stream run with only the object model converted, the original pose and person models, 10 GPU slots, 10-second warm-up and 20-second window, throughput was **30.33 FPS**, with **431 late and 4 dropped**. The previous all-original 30-stream run was 28.40 FPS, 550 late and 38 dropped. This is one short run, close to the offered 30 FPS, and does not establish maximum capacity. [Raw metrics](optimization-fp16-table.json). FP16 output and resulting table states were not compared on aligned frames or against ground truth; no claim about accuracy is possible.

TensorRT was not benchmarked: no `libnvinfer` was found in the test container. [ONNX Runtime's TensorRT documentation](https://onnxruntime.ai/docs/execution-providers/TensorRT-ExecutionProvider.html) describes its separate runtime requirements and optional FP16 mode; compatibility and performance must be checked for the installed ONNX Runtime/CUDA versions. FP16 conversion and TensorRT are not recommended for deployment on these results.
