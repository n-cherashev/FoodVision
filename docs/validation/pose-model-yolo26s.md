# YOLO26s-pose as a replacement for two person models

24 November 2026. A preliminary fixed-frame comparison, not a production acceptance test. The current pipeline's YOLO11x-pose and YOLO26l person detector were run in sequence and compared with one YOLO26s-pose call. Existing 10 frames from `Sample_Video_1.mp4` at 10, 30, ..., 190 seconds were decoded to 640×360 BGR. The same `InferenceInput`, `YoloOnnxModel`, `PersonDetector` and posture heuristic from the current code were used. Baseline pose input 1280×1280, baseline person input 640×640, candidate input 640×640. Baseline thresholds pose 0.08 and person 0.10; candidate pose/person threshold 0.08. One initial warmup, then one run per frame on RTX 5070 Ti, ONNX Runtime CUDA, in an isolated container. Times exclude preprocessing and model loading; they are single-worker measurements and do not predict multi-camera throughput.

The 10-frame median was **36.97 ms** for the two baseline model calls including their existing decoding, versus **7.12 ms** for the candidate call including decoding. Baseline returned 89 person detections over the ten frames; candidate returned 67. Greedy one-to-one matching at IoU ≥ 0.5 paired 48 of them. For 21 of those 48 pairs, the current per-person `Seated` flag differed. These are differences from the current algorithm, not precision, recall, or proof that either result is correct. The model scores are not calibrated to each other, and pose absence in the baseline can result in a `false` seated flag. Table state uses temporal context and was not assessed. Ten frames from one camera cannot establish accuracy or runtime capacity.

The candidate shows a substantial isolated inference speed opportunity but does not preserve the current frame-level results in this check. It should not be substituted without labelled evaluation and a multi-stream pipeline benchmark. Raw [baseline](pose-model-baseline.json) and [candidate](pose-model-yolo26s.json), [probe and comparison script](../../scripts/experiments/pose-probe/).

## Short multi-stream experiment

Using a separate benchmark build with [this patch](pose-model-benchmark.patch), YOLO26s-pose replaced both person calls; the existing object model still ran each frame. The old person detector session remained loaded and was called once during warmup, but was not called for measured frames. GPU concurrency was 10; after a 10-second warmup, measurements covered 20 seconds. At 30 streams: 29.86 FPS, 0 late, 0 dropped. At 40: 33.99 FPS, 7 late, 1 dropped; a repeat returned 38.38 FPS, 71 late, 37 dropped. At 50: 47.98 FPS, 207 late, 46 dropped. The results are short and variable; in particular the 40-stream result was lower than 50 and changed in the repeat, so these runs do not establish a maximum or identify the bottleneck. A full-duration repeat and quality evaluation are required. The benchmark uses raw WebSocket clients and does not measure browser rendering. [Series raw metrics](pose-model-yolo26s-capacity.json), [40-stream repeat](pose-model-yolo26s-40-repeat.json).
