# Experiment 1: reuse the object detector for people

24 November 2026. Experimental benchmark only: use class 0 from the existing YOLO11x object detections, then attach YOLO11x-pose posture using the same matching logic as the current person detector. The YOLO26l inference is skipped, but its session is still loaded; this does not measure the VRAM saving from removing the model. The application algorithm was not changed. The exact experimental patch is [here](optimization-experiment.patch).

The source video, 640×360 frames, 1 analytics FPS, 10 GPU slots, 10-second warm-up and 20-second measurement window match the earlier [baseline](concurrency-tuning.md). One run per configuration; 30-stream baseline: 28.40 FPS, 550 late and 38 dropped. Experimental 30 streams: **30.30 FPS**, 0 late, 0 dropped. This is offered-load limited; it does not establish peak throughput. At 40 streams the experiment delivered **34.18 FPS**, with 683 late and 122 dropped, so 40 streams at 1 FPS is not sustainable in this short run. See [30-stream raw metrics](optimization-reuse-detector.json) and [40-stream raw metrics](optimization-reuse-detector-40.json). These tests do not measure 40 browser canvases.

Quality is unresolved. The previous [ten-frame comparison](person-model-comparison.md) observed people missed by YOLO11x that YOLO26l found, including on the 170-second frame. That comparison has no independent annotations and is not a precision/recall evaluation. Do not replace the model on this evidence. No matched frame-by-frame table-state comparison was collected in this throughput run.
