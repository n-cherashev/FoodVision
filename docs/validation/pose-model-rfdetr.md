# RF-DETR Keypoint Preview as a replacement for two person models

25 November 2026. This experiment compares a single RF-DETR Keypoint Preview ONNX call with the current sequence of YOLO11x-pose and YOLO26l-detect. Both runs use the same ten previously extracted 640×360 BGR frames from `Sample_Video_1.mp4` at 10, 30, ..., 190 seconds. The baseline was produced from the current source code in [pose-model-baseline.json](pose-model-baseline.json). RF-DETR used its export metadata: BGR to RGB, 576×576 bilinear resize without antialiasing, ImageNet normalization, class `1` only (`person` according to the exported model metadata), and the package's documented top-k selection plus keypoint uncertainty score fusion.

The RF-DETR GPU session reported `CUDAExecutionProvider` before inference. It used the official exported `rfdetr-keypoint-preview.onnx`, SHA-256 `515ddb658cfa19327ec9fa6152e0ed05d77ab94942b1208b6f998334c1a7e9c7`. The probe warmed up once, then processed all ten frames serially. The repeated run records each stage on each frame: median ONNX inference was **16.29 ms**, median decoding was **3.23 ms**, and the directly recorded per-frame model-plus-decoder median was **19.55 ms**. The directly recorded full RF-DETR probe median, including preprocessing, inference, and decoding, was **25.13 ms**. The current two-model baseline median is **36.97 ms**, but its `totalMs` excludes input preparation; therefore only its comparison with RF-DETR's 19.55 ms model-plus-decoder metric is timing-compatible. Neither combined metric is inferred by adding or subtracting separate medians. This is a single-worker fixed-frame measurement, so it does not establish multi-camera capacity.

At the official smoke-test threshold 0.08, RF-DETR returned 94–100 candidates per frame. This is a score-calibration issue, not evidence of recall. A sensitivity sweep returned 978 candidates across ten frames at 0.08, 243 at 0.25, 150 at 0.30, 77 at 0.40, and 33 at 0.50; the baseline returned 89. For a *diagnostic only* overlap check, threshold 0.40 produced 77 candidate detections, 62 one-to-one matches with baseline at IoU ≥ 0.5, and 18 disagreements in the derived `Seated` flag. The threshold was selected only because its count is near the baseline; it is not a quality-calibrated production threshold and must not be used to claim precision or recall.

RF-DETR is a technically viable one-call replacement for the person detector plus pose model, and its fixed-frame model-plus-decoder time is lower than the current pair. It does **not** preserve the current derived posture signal in this check, and neither the baseline nor candidate has been compared with human labels. A production decision needs labelled people and seating transitions, score calibration on a validation set, an adapter in the C# pipeline, and a multi-stream benchmark with the object/table model still active.
