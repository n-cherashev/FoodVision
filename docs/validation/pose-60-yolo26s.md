# YOLO26s-pose: 60-frame comparison

25 November 2026. Compared the current YOLO11x-pose + YOLO26l-detect pipeline with YOLO26s-pose on the same 60 frames, sampled at 1 FPS from six ten-second intervals of the source video. [Manifest and source hashes](pose-evaluation-manifest.json); [sampling script](../../scripts/experiments/frame-sampling.ps1). All frames are 640×360 BGR. The C# probe invokes the current production preprocessing and detection/posture heuristics, with baseline pose input 1280×1280 and person input 640×640, candidate input 640×640. Baseline pose/person thresholds are 0.08/0.10 and candidate pose threshold is 0.08. These are different score scales and are not calibrated against labels.

Baseline returned 501 detections; YOLO26s returned 387. Greedy one-to-one matching at IoU ≥ 0.5 produced 297 pairs; 85 pairs differed in the derived per-frame `Seated` flag. Matches, counts and disagreements compare implementations, not precision, recall or table-state correctness. The model's score and box overlap thresholds and incomplete baseline pose matches affect these values. The segments are 10 seconds each, so they do not establish correctness of full-video occupancy transitions. One camera, no independent labels.

On this run, single-worker median model calls plus decoding, excluding preprocessing, were 34.33 ms baseline and 6.48 ms YOLO26s. These measurements are not multi-camera throughput; the separate [35-stream full-video run](yolo26s-full-35.md) measures the candidate with the table model. See [raw baseline](pose-60-baseline.json), [raw candidate](pose-60-yolo26s.json), [frame-level comparison](pose-60-yolo26s-summary.json) and [probe](../../scripts/experiments/pose-probe/).
