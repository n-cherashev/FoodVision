# FoodVision

Пилотный сквозной сценарий: загрузка видео статичной камеры, обнаружение столов, оценка присутствия сидящих гостей и просмотр результата вместе с оригинальной записью.

## Запуск на Windows с Docker Desktop и NVIDIA GPU

1. Установите Docker Desktop с поддержкой NVIDIA GPU и свежий драйвер NVIDIA.
2. Убедитесь, что подготовленная модель `models/yolo11x-pose.onnx` находится в папке `models/`.
3. Скачайте COCO-модель обнаружения столов: `powershell -ExecutionPolicy Bypass -File scripts/setup-models.ps1` (исходная модель — [YOLO11-ONNX](https://huggingface.co/unileon-robotics/YOLO11-ONNX)).
4. Запустите `docker compose up --build`.
5. Откройте <http://localhost:8081>, выберите видео и дождитесь ответа анализа.

Интерфейс доступен на порту `8081`, API и health-check — на `8080` (`/health`). Модели монтируются в контейнер только для чтения. Обработка работает на CUDA GPU; автоматического перехода на CPU нет. Для локального запуска API без Docker нужны .NET 11, FFmpeg и обе модели в путях, заданных в `backend/FoodVision.Api/appsettings.json`.

## Анализ

FFmpeg декодирует видео по кадру в секунду. Поиск столов идёт с начала ролика до первого кадра с обнаруженными столами; это позволяет пропустить заставку перед записью с камеры. Набор столов затем фиксируется, номера и координаты действуют только в рамках текущего видео. Pose-модель распознаёт человека, COCO-модель — стол и положение человека относительно него. Согнутое колено и расположение бёдер около стола дают гипотезу «занят»; человек рядом со столом без уверенной позы даёт «нужна проверка». Отсутствие подходящих людей считается «не занят». Это эвристический исследовательский прототип: определение посадки по общедоступным COCO-моделям нужно отдельно сверить с видео конкретной камеры. Состояние «не занят» не означает, что стол подготовлен к следующей посадке.

Положение столов в API нормализовано в диапазоне 0–1 по исходному кадру. Все временные отметки и интервалы ограничены длительностью записи. Результат не сохраняется: исходное видео временно записывается на диск во время обработки и удаляется после ответа, ошибки или отмены запроса.
