# FoodVision: сравнение C# и Python для видеоаналитики

Эксперимент исследует основу сервиса видеомониторинга для точек общепита: насколько быстро два минимальных консольных приложения читают видео, подготавливают кадры и запускают одну модель компьютерного зрения. Долгосрочные сценарии — обнаружение людей, оценка очередей и контроль видимых действий. Текущий проект — измерительный прототип, а не готовый сервис мониторинга.

## Задача эксперимента

Сравнить два стека на одном компьютере, одной видеозаписи и одной модели. Каждый worker последовательно обрабатывает кадры и повторяет полный проход заданное число раз; workers работают одновременно и выводят общую пропускную способность.

| Компонент | C# | Python |
|---|---|---|
| Среда | .NET SDK 11.0.100 | Python 3.14.3 |
| Видео и изображения | OpenCvSharp 5 | OpenCV Python 5 |
| Вычисления | ONNX Runtime 1.32.0 | ONNX Runtime 1.32.0, NumPy |
| Модель | YOLOv5n, ONNX, FP16 | Та же модель |
| Устройство | CPU | CPU |

Стандартные функции продукта — обработка событий, работа с камерами по RTSP, трекинг, уведомления, интерфейс и хранение — здесь не реализованы. Результаты модели не декодируются и не отображаются: приложение замеряет inference, но не показывает найденных людей.

## Что происходит при запуске

1. Программа создаёт отдельную ONNX-сессию и буферы для каждого worker; модель загружается до общего замера.
2. Для каждого кадра изменяет размер до 640 × 640, переводит BGR в RGB, нормализует значения и формирует входной тензор NCHW FP16.
3. Запускает модель на CPU через ONNX Runtime.
4. Одновременно запускает заданное число workers и выводит их показатели, общее время и aggregate FPS.

Для обеих версий число потоков OpenCV и intra/inter-op ONNX Runtime установлено в 1 на worker, чтобы не создавать вложенный параллелизм. Модель создаётся до замера, а видео открывается до замера каждого прохода. В каждом кадре обе программы выполняют одну цепочку: resize, BGR → RGB, `float32 / 255`, HWC → NCHW, `float16`, inference. Aggregate FPS вычисляется как суммарное число кадров всех workers, делённое на общее wall-clock время.

Используется тестовый фрагмент `FoodVision-py/data/sample.avi`: первые 50 кадров [примера OpenCV vtest.avi](https://github.com/opencv/opencv/blob/4.x/samples/data/vtest.avi). Модель — [YOLOv5n из релиза Ultralytics](https://github.com/ultralytics/yolov5/releases/tag/v7.0). При дальнейшем использовании модели проверьте условия её лицензии и лицензии обучающих данных.

## Исторические результаты на Windows

16 ноября 2026 года, Intel Core Ultra 7 265KF, 10 последовательных проходов по 50 кадров. Обе программы запускались раздельно.

| Стек | Версии | Среднее время одного прохода | Скорость |
|---|---|---:|---:|
| C# | .NET SDK 11.0.100; ONNX Runtime 1.32.0; OpenCvSharp 5.1.0.20261115 | 2,216 с | 22,56 FPS |
| Python | Python 3.14.10; ONNX Runtime 1.32.0; OpenCV 5.0.0.93; NumPy 2.5.5 | 2,374 с | 21,06 FPS |

Это исторический результат конкретных реализаций и оборудования, а не универсальный рейтинг языков. Десять проходов по короткому видео не отражают длительную работу, множество камер, сеть или GPU. Актуальный запуск на macOS и предыдущие результаты приведены в [RESULTS.md](FoodVision-py/RESULTS.md).

## Запуск на Windows

Нужны .NET SDK 11.0.100 и Python 3.14.3 x64. У ONNX Runtime 1.32.0 на момент проверки не было готового Windows wheel для Python 3.15. Зависимости Python устанавливаются в отдельное окружение. Команды выполняются из корня репозитория в PowerShell.

```powershell
cd FoodVision-py
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe benchmark.py data/sample.avi data/yolov5n.onnx 10 10
```

В отдельном терминале из корня репозитория:

```powershell
cd FoodVision-cs
dotnet run -c Release -- ..\FoodVision-py\data\sample.avi ..\FoodVision-py\data\yolov5n.onnx 10 10
```

В обоих примерах `10 10` означает 10 проходов на каждого из 10 одновременных workers: всего 5 000 кадров для sample.avi. Последний аргумент необязателен и по умолчанию равен 1. Можно указать другой локальный файл и совместимую ONNX-модель; приложение ожидает совместимую форму входа и не является универсальным обработчиком моделей.

## macOS

Python-окружение нужно создать заново на Mac. C# автоматически выбирает `OpenCvSharp5.runtime.osx.arm64` на Apple Silicon; для Intel требуется заменить его на `OpenCvSharp5.runtime.osx.x64`. .NET SDK и Python должны соответствовать архитектуре машины. Текущий код использует CPU, а Core ML и Neural Engine требуют отдельной настройки и проверки модели.
